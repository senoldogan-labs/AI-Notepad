## Scope and evidence

The audit identifies history-dependent protocols encoded across flags, tasks, resource handles, persisted files, SQL/R2/KV records, timestamps and DOM state. It is architectural evidence, not proof that each protocol is faulty. The registry below has 175 labels; these are overlapping inventory entries, not 175 distinct bugs or unique state machines. Source links refer to the baseline above.

Runtime coverage includes `App/`, `iOS/`, `iOSKeyboard/`, `Watch/`, `Packages/AINotepadCore/`, `Packages/AINotepadWatchLink/`, `server/src/` (API and MCP/assistant Workers), and `web/src/`. Generated/vendor code, SDK internals, CI/release machinery, promotional tooling, translations and media are outside the runtime inventory. Existing tests inform classification. Static analysis cannot prove that no additional protocol exists.

An entry closes through one of three outcomes: a concrete regression is fixed; a significant implicit protocol gains a single typed decision boundary with adapter evidence; or bounded existing state is retained with an explicit invariant and verification evidence. A new enum alone is insufficient. Do not refactor an ordinary preference, selection or animation solely because its value changes.

## Architecture contract

1. Keep independent lifecycles independent. Use domain-specific state/event/effect value types and pure transitions where ownership or legal transitions are distributed. Do not introduce a universal FSM framework, new state library, or one application-wide enum.
2. Keep IO handles in thin existing adapters. Pure state carries logical owner, recording/work/request identity, generation, observations and typed outcomes. A late completion cleans up its own resources without publishing into a different owner.
3. Reuse current recording IDs and account-data gates. Keep `HostedScopeStamp` for feature-center generations; the installed session supplies one `AccountSessionOwner` epoch because a feature generation is not a session identity. That epoch distinguishes account A before and after A → B → A. Pure decision tests alone do not prove adapter checks happen at the required publication/IO boundaries.
4. Persisted files, D1/R2/KV/provider records are the durable authority. Use existing atomic writes, D1 transaction/CAS guards, epochs, idempotency keys and outboxes. In-memory state cannot claim that an external effect is durable before its receipt is durable.
5. Separate behavior-preserving extraction from a new guarantee. Missing crash checkpoints, orphan cleanup or deletion progress require a separately reviewed additive migration/journal slice. Each affected package closes its durability requirement or records a blocker; extraction alone cannot close it.
6. Preserve deployed JSON/file names, App Group/WCSession payloads, API status/error contracts, encrypted formats and supported OS versions in initial slices. Keep KeyboardCore dependency-free and WatchLink Foundation-only. Schema evolution is additive and compatible with both running Workers until rollout completes.
7. Delivery with an ambiguous provider outcome remains uncertain unless provider idempotency or reconciliation proves completion. Do not automatically replay an uncertain external side effect. State local attempt deduplication precisely; do not promise cross-service exactly-once execution.
8. This work does not authorize new silent fallbacks. Preserve intentional existing policies during extraction; propose any policy change separately with evidence. Surface actionable failure and retain recoverable work. Retry the same retryable external call with bounded backoff and per-attempt structured warnings; do not repeat already billed work to retry a later stage.
9. Added repository content is English. Use strict Swift/TypeScript types, named data, pure business decisions and explicit parameters. Keep established tools; do not combine this program with a lint/toolchain migration or broad test rewrite.

## Explicit models to preserve

Retain the main recorder (`RecorderState`/`recorderStep`), microphone capture, call-end detection, pause clock/gate, segmentation, screen capture run, hosted session/account-data gates, checkout lock, updater, assistant pass scheduler, paywall, CallKit, Watch transfer/import, keyboard Ask sheet/readiness/setup, server meeting/phone/refresh/referral/trial/subscription/withdrawal, and web session/checkout/admin-load/share-view/plan-status models. Surrounding resource, durability or completion protocols may still need changes. A self-contained enum with centralized transitions is already explicit without a reducer function.

## Independent design review and dissent

Three independent domain reviewers inspected the proposed direction: Core/shared UI and macOS persistence; iOS/keyboard/Watch; server/web. The primary author inspected App adapters and reconciled coverage.

| Review issue | Decision and rationale |
| --- | --- |
| Prioritize ownership and durable save order | Start with P01/P02. Mac pending delivery/task/reminder maps are consumed in `applyingPendingReminders` before the final save. First characterize whether disk receipts already cover failure; preserve pending evidence until successful persistence if a gap exists. This is a hypothesis, not a reproduced defect. |
| Preserve explicit models | APP-07 overlaps CORE-C23; APP-19 and APP-34 share a writer barrier; APP-46 is a small capture binding protocol; CORE-C22 folds into CORE-C07. Extract only the missing adapter protocol. |
| Extraction does not establish crash safety | Accepted server objection. P20/P21/P25 require durable-boundary tests and explicit persistence work where checkpoints are insufficient. A local enum cannot replace an outbox or transaction. |
| Keep bounded state simple | Accepted mobile/server objections. P29 retains simple status/confirmation/timer state by default. A lower Boolean count is not an acceptance criterion. |
| Preserve cross-process compatibility | Accepted mobile objection. Initial extraction keeps deployed shapes; adapters translate internal state without importing Core into KeyboardCore/WatchLink. Durable work remains account-tagged and is readmitted under fresh process epochs. P16 explicitly gates an additive/versioned Watch envelope if queued mutating commands lack provable owner evidence; unscoped ambiguous commands fail explicitly. Test old/new endpoints. |
| Require appropriate hardware evidence | Simulator cannot certify real dictation output or Watch file delivery. Those acceptance checks need paired hardware, separately from deterministic custody tests. Experimental call capture remains device-gated. |
| Keep failure cleanup separate from commit | Accepted final Core review. Failed/superseded work releases its own job/task/keep-awake resources while preserving checkpoints/pending marks and never releasing a replacement work ID. P01 tests a shared filesystem commit seam used by both app adapters. |
| Preserve uncertainty and concurrency | Do not replay ambiguous external effects or force parallel conversion/transcription/speaker work into one linear phase. Preserve telemetry's intentional delivery policy unless a separate behavior change is chosen. |
| Apply sensitive-change shipping checkpoints | Repository AGENTS.md requires stopping/reporting before shipping auth, payments, migrations or production infra changes. Prepare concrete code and checks first. Privacy/epoch/revocation changes get explicit technical review as well. |

Final draft review also resolved ambiguous server paths, declared the Live Activity API/test seam, separated durable account tags from process epochs, and added Watch request/reply and queued-command ownership acceptance. Necessary call-audio writer changes have a concrete XcodeGen test-target path; retained writer contracts require no new target. No reviewer proposed a new FSM dependency or wholesale replacement of existing reducers. There is no unresolved architecture dissent. The existence and exact storage shape of missing durability checkpoints remain evidence-dependent implementation decisions with explicit gates.

## Program completion contract

Every registry row must link to its merged implementation PR or a reviewed retain decision and concrete evidence. Necessary sensitive changes may remain unshipped pending the required owner checkpoint; the program then remains incomplete. Baseline failures, unavailable hardware, missing crash guarantees or skipped relevant tests are blockers, never passing results. P30 verifies cross-layer traces and registry coverage without treating source-anchor validation as runtime proof.
